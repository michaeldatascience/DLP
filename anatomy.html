Transformer Anatomy

Where every parameter in a transformer physically lives, and how to count them without memorising anything. Change the dimensions below and watch the model's size assemble itself. Four past-paper questions are solved at the bottom, then you're quizzed.

01

A transformer keeps its parameters in three places

That is the whole idea. Every parameter-counting question in this course is just asking you to add up three buckets. Before the formulas: parameter means one learnable number — a single cell inside a matrix. When a model is called "7B", that is a count of these cells.

Place 1 · once per model

The lookup tables

V·d + ctx·d

One row per vocabulary entry, so the model can turn a token id into a vector. Plus one row per position, so it knows where in the sentence each token sits. Both rows are d numbers wide.

Place 2 · once per block

Attention projections

4 · d²

Four square matrices, each d×d: query, key, value, and the output projection that mixes the heads back together. Four squares, hence 4d².

Place 3 · once per block

Feed-forward network

2 · d · 4d = 8 · d²

Widens each vector from d to 4d, then squeezes it back to d. Two matrices of d×4d. Twice the size of the attention beside it.

The sentence that replaces the formulas "Attention is four, feed-forward is eight, so twelve per block." Add the two lookup tables once, and you can rebuild any model's size from its config. That is the entire skill.

Why the exam accepts a range instead of an exact number This count ignores bias vectors and layer-normalisation parameters. On GPT-1 those come to 46,080 out of 116.4M — four hundredths of one percent. That is why past papers ask for "2.3 to 2.5" rather than an exact figure, and why the lecture's GPT-1 total is quoted as both 116.46M and "around 117 million" on consecutive slides. Count the three buckets and you will always land inside the accepted band, so never spend exam time hunting for biases.
03

Three decoys the paper plants

Each of these appears in a question specifically to be used, and in every case the right move is to ignore it. Verify each one on the panel above.

Decoy 1 · the number of heads Drag the heads slider from 1 to 64. The total does not move. Heads split the existing d×d matrices into h slices of width d/h — they do not add matrices. Twelve heads of width 64 is exactly 12 × 64 = 768 numbers wide, which is the same single d×d matrix.

T1 Q19 gave you "12 attention heads" and the answer was 4d², using d alone.
Decoy 2 · the sequence length T T is how many tokens are in this particular input. Parameters are the model's permanent furniture; they exist before any input arrives and do not change when a different sentence shows up. T affects how much activation memory a forward pass needs, and it drives the O(T²) cost of attention — but it never appears in a parameter count.

T1 Q19 opened with "a very short sequence of only 3 tokens". It was irrelevant.
Decoy 3 · the context length This one is subtler, because ctx does appear — but only in the smallest bucket. Set d to 2048 and drag ctx from 2048 to 8192: the total barely moves, because you are only adding rows to the position table while the blocks stay untouched.

GA4 asked how the memory to load a 7B model changes when context goes 2048 → 8000. Answer: by about 12.2M parameters, roughly 0.05 GB on a 28 GB model. It stays 28 GB.

Now solve the real questions

Every parameter-counting question from both past Quiz-1 papers and the graded assignments. Read the question, work it on paper, then open the steps.

2026 T1 · Q19 · 4 marks

A GPT-style transformer block has an embedding dimension of 768 and uses 12 attention heads. Consider a processing task with a very short sequence of only 3 tokens (T = 3). Compute the total number of weight parameters (ignore biases) in the self-attention module — specifically the Query, Key, Value and Output projection matrices. Report in millions, to one decimal place.

1
Spot the decoys first. Heads = 12 and T = 3 are both named, and neither belongs in a parameter count. Cross them out before computing anything.
2
Four named matrices — Query, Key, Value, Output — each d × d.
3
4 × 768² = 4 × 589,824 = 2,359,296.
4
In millions: 2.359 → 2.4. The accepted band was 2.3 to 2.5.
4d² = 4 × 768² = 2.36M
2026 T1 · Q20 · 4 marks

You are training a decoder-only language model with a vocabulary of 32,000, maximum context length 2048 and embedding dimension 1024. The model uses learned positional embeddings. Calculate the total number of parameters in the embedding layer (token + positional). Report in millions, to one decimal place.

1
"Learned positional embeddings" is the licence to count the second table. Had it said sinusoidal, that term would be zero.
2
Token table: 32,000 × 1024 = 32,768,000.
3
Position table: 2048 × 1024 = 2,097,152.
4
Sum: 34,865,152 → 34.9. Accepted band 34.7 to 35.1.
V·d + ctx·d = 32.77M + 2.10M = 34.9M

GA3 · Week 3 · and GA4 · Week 4

(a) Take default BERT (d = 768) and double the context length from 512 to 1024 in the config. Enter the change in parameter count, in millions. (b) A 7B model has context 2048 and embedding dimension 2048. If context rises to 8000, how much memory in GB is needed to load it in fp32?

1
(a) Only the position table changes. Nothing else in the model knows the context got longer.
2
Δ = Δctx × d = (1024 − 512) × 768 = 512 × 768 = 393,216 → 0.393M. Band 0.38 to 0.41.
3
(b) Same reasoning, bigger numbers: Δ = (8000 − 2048) × 2048 = 12,189,696 extra parameters.
4
In fp32 that is 12.19M × 4 bytes ≈ 0.049 GB — on a model that already weighs 7e9 × 4 = 28 GB.
5
So the answer stays 28 GB. The accepted band was 26 to 30, deliberately wide enough that the tiny increase cannot change your answer. The question is testing whether you know context length is nearly free.
Δparams = Δctx × d  ·  (a) 0.393M  ·  (b) still 28 GB
