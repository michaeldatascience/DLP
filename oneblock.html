DA5013 · Concept 05 · Weeks 3 & 4

One Block, End to End

Three tokens, four dimensions, every number visible. The same three tokens go through the feed-forward network, back through it, then through attention with two heads — and then LoRA is applied to one of the matrices you have just watched work. Nothing is abstract and nothing is skipped.

00

The setup, and the colour code

A real transformer has d = 768 or more. This one has d = 4, so every matrix fits on screen. The structure is identical — only the numbers are small. Three tokens, four dimensions each.

Three kinds of thing appear on this page, and telling them apart is the whole lesson. The colours never change meaning.

WEIGHTLearned. Persists forever. One entry per parameter. These are what "7B parameters" counts.
ACTIVATIONComputed fresh each forward pass, thrown away after the backward pass. One entry per token per dimension.
GRADIENTProduced by the backward pass. Always the same shape as the weight it belongs to. Discarded after the update.
The one question that classifies everything Does this thing have one number per parameter, or one number per token? Weights and gradients are per parameter. Activations are per token. That single distinction explains why activations grow when you raise the batch size and why the model's memory does not.
01

Feed-forward, going forwards

The feed-forward network widens each token's vector, applies a non-linearity, and squeezes it back. Here it widens 4 → 8. A real one widens 4× (768 → 3072); I use 2× so the matrices fit. Each token is processed independently — no token looks at any other in this part.

Step 1

Widen: multiply by the first weight matrix

Each of the 3 token rows is multiplied by W1. A row of 4 numbers meets a 4×8 matrix and comes out as 8 numbers.

Step 2

Non-linearity: ReLU keeps the positives

ReLU(x) = max(0, x). Negative entries become zero. This is where the network gains the ability to express something other than a straight line. Real GPT uses GELU, a smoothed version of exactly this shape.

Notice the zeros. They matter in a moment — a zero here blocks a gradient later.

Step 3

Squeeze: back down to width 4

W2 takes the 8 numbers back to 4, so the block's output has the same shape as its input. That is what lets you stack blocks.

Count what is on screen Weights: W1 is 4×8 = 32 and W2 is 8×4 = 32, so 64 parameters. In the general case that is 2 · d · 4d = 8d² — the "feed-forward is eight" from Transformer Anatomy.

Activations: X 12, H 24, A 24 = 60 numbers. Add a fourth token and the weights do not change at all, but the activations grow to 80.
02

Feed-forward, going backwards

Something upstream tells us how wrong Y was. That arrives as dY, one number per entry of Y — "nudge this entry down, that one up". The job now is to turn that into a correction for every weight.

Step 4

The gradient of W2 — and why A had to be kept

dW2 = Aᵀ @ dY. Read that carefully: computing how to correct W2 requires A, the activation from step 2.

This is the entire reason activations cost memory. They are not stored because someone chose to cache them. They are stored because the backward pass cannot run without them. Throw A away and dW2 is uncomputable.

Step 5

Push the signal back through, then the gradient of W1

Three small steps: dA = dY @ W2ᵀ sends the signal back across W2; dH = dA ⊙ (H > 0) passes it through the ReLU, zeroing wherever the forward pass zeroed; then dW1 = Xᵀ @ dH.

That middle step is why the zeros mattered. A unit switched off in the forward pass receives no gradient in the backward pass.

The shape fact to carry away W1 is 4×8 and dW1 is 4×8. W2 is 8×4 and dW2 is 8×4. A gradient always has exactly the shape of the weight it corrects.

So "gradients cost the same as weights" is not a coincidence or an approximation — it is forced by the arithmetic. And momentum and variance are also one-per-parameter, because they are running averages of these gradients. That is where sixteen bytes per parameter comes from, and you have now watched it happen.
03

Attention, on the same three tokens

The feed-forward network never let tokens see each other. Attention is the part that does. Same X as before, same four dimensions.

Step 6

Three projections of the same input

X is multiplied by three separate weight matrices to produce three different views of the same tokens. The names are a filing-cabinet metaphor: Query is what this token is looking for, Key is what each token advertises about itself, Value is what it actually hands over if chosen.

All three are 4×4 here, so Q, K and V each come out 3×4 — one row per token, exactly like X.

Step 7

Split into two heads — and notice no parameters are added

Two heads means: cut each of Q, K, V down the middle. Head 0 takes columns 0–1, head 1 takes columns 2–3. Each head gets width d/h = 2.

Nothing new is created. The same 4×4 matrices are being read in two halves. This is why the heads count is a decoy in parameter questions — doubling the heads just slices the same numbers more finely.

Step 8

Each head: score, mask, softmax

scores = Qₕ @ Kₕᵀ / √2 gives a 3×3 grid — how much each token wants to attend to each other token. The √2 is √(head width) and is only a normaliser, keeping the numbers in a range where softmax behaves.

Then the causal mask sets everything above the diagonal to −∞, so no token sees the future, and softmax turns each row into probabilities summing to 1.

Look at the first row after softmax: it is always 1, 0, 0. Token 1 has no past, so it can only attend to itself. And the score grid is 3×3 — T×T — which is the O(T²) term.

Step 9

Mix the values, stitch the heads, project out

Each head computes P @ Vₕ — a weighted blend of value rows, using the attention probabilities as the weights. The two heads' outputs are concatenated back to width 4, then passed through a fourth matrix W_O.

The whole block, counted Attention: four 4×4 matrices = 64 parameters, which is 4d². Feed-forward: 64, which is 8d² at this reduced width (2d instead of 4d). At real proportions the FFN is twice the attention, giving 12d² per block.

Every number in Q, K, V, the score grids and the outputs is an activation — gone after the backward pass. Only the four matrices persist.
04

Now LoRA, on W_Q

You have just watched W_Q do its job in step 6. Fine-tuning normally means computing a gradient for all 16 of its numbers and keeping momentum and variance for each. LoRA says: don't.

Step 10

Freeze the matrix; learn a correction beside it

W_Q is frozen — it still runs in every forward pass, it still sits in GPU memory, but no gradient is ever computed for it. Instead two thin matrices are added: A of shape 4×1 and B of shape 1×4. Their product A @ B is 4×4 — the same shape as W_Q.

The model now uses W_Q + A@B wherever it used W_Q. The 1 in those shapes is the rank r.

Why B starts at zero A@B is all zeros at step 0, so W_Q + A@B equals W_Q exactly. The adapted model starts out identical to the pretrained one and departs from it only as training proceeds. Initialising both to random would corrupt the pretrained behaviour on the very first forward pass.
Step 11

After a few steps, B has moved

Only A and B received gradients, so only they changed. Their product is now a non-zero 4×4 correction, which is added to the frozen matrix to give the effective one.

The toy does not show the saving — the formula does Here: 8 trainable against 16 frozen. That is 50%, which is no saving at all. That is not a flaw in the example; it is the point. The ratio is

2·d·r / d² = 2r / d

At d = 4, r = 1 that is 0.5. The win appears only when d is large and r stays small — and r stays small because the correction a fine-tune needs is simple even when the matrix is huge. Move the sliders.
— of one matrix is trainable  ·  2r/d
Head-only fine-tuning, for contrast LoRA touches every layer with a small correction. Head-only touches one new layer and freezes everything else. Its size is just d × num_labels — for d = 2048 and 8 entity labels that is 16,384 parameters, roughly 0.0002% of a 7B model. Hundreds of times smaller than LoRA, and correspondingly less able to adapt: the body cannot change at all, so it only works when the pretrained features already suit your task.
