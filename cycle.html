The Whole Cycle

From raw text to a model you can use, in three parts: the tokenizer, the transformer, and inference. Pick a model size below and every shape and number on the page updates to match.

The whole cycle in one lineText becomes ids. Ids go through a transformer that scores every possible next token. During training the scores are corrected; during inference the best one is picked and the loop runs again.

Three things that tie the parts together
  • The same frozen tokenizer is used in training and inference. A new tokenizer would give different ids, and the learned embedding rows would no longer match.
  • V appears twice: as the rows of the token table at the input, and as the number of scores at the output.
  • The text itself is the answer key in pre-training. The next token is always right there in the corpus, so no one labels anything.

Part 1 · The tokenizer weeks 1–2

The jobTurn text into a list of integers, in a way that is fixed once and reused forever. The tokenizer is built from the corpus before the model exists. It is learned by counting, not by gradient descent.
1

Collect the raw text nothing learned

Load a dataset from the Hub (week 1), then .map() and .filter() to clean it: drop empty rows, fix columns. At this point it is only strings.

the cat sat on the mat the cat ran the mat sat on the cat
2

Clean and cut into words fixed rules

The normalizer tidies the text (for example lower-case). The pre-tokenizer splits it on spaces. In the toy, _ marks a word end.

"the cat sat" → the_ cat_ sat_
3

Train the algorithm until it has V tokens learned by counting then frozen

You choose V. BPE merges the most frequent pair, WordPiece merges the pair with the best score, Unigram starts big and drops tokens. Each stops at V. The corpus decides which tokens; you decide how many.

Output: a vocabulary of V entries, each with an id, plus the merge rules (or token probabilities for Unigram).

toy vocabulary: _ a at_ cat_ m n o r s the_ (V = 10)
4

Encode: text to pieces to ids frozen tokenizer

Replay the merge rules, then look each piece up. The post-processor adds special tokens (BERT: [CLS] at the start, [SEP] at the end). After this line there is no text left in the system.

"the cat sat" → [the_, cat_, s, at_] → [9, 3, 8, 2]
one input: T integers
5

Batch: pad, truncate, and record the padding frozen tokenizer

padding=True pads every input to the longest in the batch. truncation=True cuts at the limit; without it nothing is cut. The attention_mask says 1 for a real token and 0 for padding. The tokenizer writes it; the model's attention reads it later.

input_idsattention_mask
6

For pre-training only: pack the whole corpus into blocks frozen tokenizer

Tokenize everything, join all the ids into one long stream, cut it into pieces of exactly the context length, and drop the short last piece. No padding is needed. These pieces become the training inputs.

tokens per piece, so T = context
The exam hooks
  • Bigger V: shorter sequences but a bigger embedding table. Never both better.
  • A tokenizer that shatters your text or gives many [UNK]s: retrain it on in-domain text. Nothing in the model can fix it.
  • Special tokens and their ids are model-specific. GPT-2 has no pad token until you set one.

Part 2 · The transformer weeks 3–4

The jobTake ids in, give back a score for every one of the V tokens, and learn from how wrong the scores were. Three stages: build it, train it on the next-token task, then adapt it to your own task.

Build

1

Choose the shape you choose

You pick V (already set by the tokenizer), d, L, h and the context length. Those fix every parameter count:

embeddings = V×d + context×d  |  one block = 4d² (attention) + 8d² (FFN) = 12d²

2

Embedding tables: ids to vectors learned by backprop

Two tables, both random at the start. The token table has one row per vocabulary entry: which token is this. The position table has one row per position: where is it. Each token's vector is its token row plus its position row. The result is called X.

token table position table
ids→X

X is a lookup, not something a network computed. T and d are unrelated: T is how long this input is, d is a fixed property of the model.

3

The blocks: attention, then feed-forward learned by backprop

Each block lets tokens look at each other (attention), then processes each token on its own (feed-forward network, FFN). Each part also adds its input back to its output (a residual) and re-scales each vector (layer-norm). Neither changes a shape. The shape going in equals the shape coming out, which is why blocks can be stacked L times.

The last layer: a score for every token learned by backprop

Each token's vector of d numbers becomes V scores, one per vocabulary entry (called logits). GPT-style models usually let this layer reuse the token table, so the course's parameter count has no extra V×d for it.

5

Loss: how wrong was the next-token guess no new parameters

The labels are the same ids shifted left by one: at each position, the token that actually came next. Softmax turns the scores into probabilities; the loss is −ln(probability of the correct token), averaged over all positions.

labels→one number: the loss

An untrained model spreads probability evenly, so its loss is about ln V = . A good training run starts there and falls.

6

Backprop, then the optimizer updates everything this is the learning

Backpropagation works out a gradient for every learnable number. AdamW then nudges each one. During training every number needs four copies: the weight, its gradient, momentum and variance. That is 16 bytes per number in fp32.

The pre-trained model knows language, not your task. The choices differ in how many numbers you train, and so in memory. Numbers below are for the model you picked.

Continued pre-training (plain domain text) and instruction tuning (instruction–response pairs) change the data, not the machinery. Their objectives differ. With lots of raw domain text and a few instruction pairs, do continued pre-training first, then instruction tuning.

Four ways to cut memory while doing this: mixed precision, gradient accumulation, gradient checkpointing (these three save activations) and quantization (saves weights). LoRA and head-only save gradients and optimizer states.

The exam hooks
  • Heads and T add no parameters. A longer context adds only Δcontext × d.
  • Training one 4B-parameter model in fp32 with AdamW: 4B × 16 = 64 GB. Loading it: 4B × 4 = 16 GB.
  • The only T² thing is the score matrix. The mask hides the future with −∞; diagonal=0 also hides the token itself, giving NaN.
  • Continued pre-training and instruction tuning do not share the same objective.

Part 3 · Inference using the model

The jobUse the finished model. It is the same forward pass as in training, with no labels, no loss, no backprop and no optimizer. A text-generating model repeats the pass once per new token. One input at a time, so B = 1 here.
1

Load the weights nothing updates

Only the weights are needed. No gradients, no momentum, no variance. So it is N × bytes per number, instead of N × 16.

Keep only the last position nothing learned

The scores at the last token say what comes next. The scores at earlier positions answered earlier questions, and are not needed now.

5

Softmax, then choose a token no loss, no labels

Softmax turns the V scores into V probabilities. Then pick one: greedy takes the highest; sampling draws at random according to the probabilities. (These two decoding choices were not in the past papers or assignments I had, so treat them as background.)

→ one id
6

Append it and go round again the loop

Add the chosen id to the input and run the pass again. This is why generating 100 tokens takes 100 passes. Stop at the end-of-text token or when T would pass the context length.

→→ …
7

Decode: ids back to text frozen tokenizer

tokenizer.decode(ids) joins the pieces back into text. This is the only point where words reappear.
